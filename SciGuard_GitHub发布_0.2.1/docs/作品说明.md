# SciGuard：基于 Agnes Harness 的预处理泄漏检查与受控演示

## 问题与目标

机器学习实验中，先用全量数据拟合预处理器、再划分训练与测试集，会让测试集信息进入预处理。SciGuard 以 SG001 规则检查这类 sklearn 风格文本模式，输出风险位置、证据和修正建议，并在 AGH 中展示检查与固定实验执行之间的控制流程。

## AGH 的核心作用

模型在 AGH 会话中理解任务、选择工具、组织调用并解释结果。SciGuard 作为普通插件行注册：

- `sciguard_check`：确定性的启发式文本检查，不执行输入代码。
- `tool_call` hook：仅针对 `run_code`。命中 SG001、空或非字符串输入、超过 32768 字符、检查异常及未闭合字符串等需复核情况会被拒绝；非目标工具直接放行。它不验证完整 Python 语法或所有实验风险。
- `sciguard_run_demo`：仅接受 risky/corrected 两种固定模板，先自行调用检查器，再通过 AGH 的 `ToolContext.exec` 执行修正版，保留宿主审批。

固定演示不是内置 `run_code` 的真实 Python runtime。宿主 hook 阻断与固定演示工具内部检查是两条不同的控制路径。

## 方法与改进

检查器屏蔽注释和字符串并保留行号，匹配 fit/fit_transform 与后续 train_test_split，关联简单数据变量及变换赋值目标。0.2.1 支持 StandardScaler 的构造调用链、模块限定写法及相应赋值识别。

实现属于启发式文本分析，不进行完整 Python 解析或跨函数数据流分析。支持匹配部分模块限定文字形式，不等于解析了真实导入或所有别名关系。

## 局限与后续方向

- CH-07 跨函数漏报保留，不声称已修复。
- 不解析完整导入、分支、循环、重赋值、别名和跨函数关系。
- 没有发现模式不意味着没有泄漏、程序正确或实验可信。
- `run_code` hook 不拦截 shell；固定演示不是任意代码安全沙箱。
- v2 排除项及原标签问题必须与指标一起披露，不能将局部 100% 称为通用检测能力。

后续方向是扩展解析与数据流支持，并建立更独立、更充分的评测集。本轮提交保持当前功能范围和失败案例。

## 模型与第三方来源

所附 trace 的 7 条 request/header 事件记录的模型标识均为 agnes-3.0-flash；本地账户 Provider 为 Agnes AI，经 AGH 账户 API 调用，用于任务组织与工具选择。模型、实验分类器和视频后期辅助的已知版本与用途见《模型与第三方使用清单》。服务未返回进一步修订编号时按实际 model ID 声明。开发曾使用 ChatGPT/Codex 辅助排查、编码与整理，历史具体后端型号仍需队员据真实记录核对，不猜填。SG001 判定来自确定性检查器，分类指标来自固定 Python 实验。

基础宿主 Agnes Harness 来自 https://github.com/AgnesAI-Labs/agnes-harness，许可证 Apache-2.0；SciGuard 包许可证 MIT。Python 实验依赖见 requirements-demo.txt。数据通过 sklearn.datasets.load_breast_cancer 加载，原始来源为 UCI Wisconsin Diagnostic 数据集；原始页面、CC BY 4.0 许可与数据集 DOI 引用已列入《模型与第三方使用清单》。不将第三方框架、组件和数据归为本队原创。
