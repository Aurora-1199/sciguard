安装 Node.js。当前项目使用 Node 24.21.0；AGH 要求 Node >=24.10。

用终端进入本公开仓库根目录，执行：

```powershell
node --test .\examples\packages\sciguard\check.test.mjs
node .\examples\packages\sciguard\benchmark\run-benchmark.mjs
node .\examples\packages\sciguard\benchmark\challenge\run-challenge.mjs
```

上述单测和三类文本评测不会执行被检查的 Python，也不会调用模型 API。评测文件写入当前仓库的 `outputs`；本包已有本次结果与日志。单测期望 16/16；基础集 20/20。原挑战集应保留 CH-07 漏报，v2 需保留 3 条排除项。

## 四、AGH 中安装并演示

1. 打开本地 AGH 网页，按官方界面配置自己的模型账户。提交材料不含 Key。
2. 工作目录选择 AGH 仓库根目录。
3. 插件来源使用 `file:./examples/packages/sciguard`；如果界面不能按预期解析相对来源，改用该复现仓库中插件文件夹的绝对 file 来源。核对包名 `@sciguard/scientific-check` 与 0.2.1，按官方安装、来源信任和启用流程处理。
4. 确认插件实际运行状态，开启新会话。检查工具使用 `sciguard_check({"code": "待检查的 Python 文本"})`；固定演示使用 `sciguard_run_demo({"variant": "risky"})` 或 `sciguard_run_demo({"variant": "corrected"})`。以上是参数结构示意，由模型实际调用工具，不是 PowerShell 命令。
5. 两种固定演示变体均声明 requiresApproval: always，由宿主处理审批。出现审批卡时，核对固定实验操作后批准本次；不要关闭审批来掩盖失败。保存工具详情的 Arguments 和 Result/Error details，不用模型复述替代调用记录。

风险模板期望 BLOCKED、executed=false；宿主界面可显示 Failed，应保留其明确的拒绝结果。修正版期望 COMPLETED、executed=true 以及实际指标。失败或审批超时应据实记录。

